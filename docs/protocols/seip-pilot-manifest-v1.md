# SEIP pilot manifest v1 — offline ledger contract

This is an engineering adapter for the [qualification protocol in #12](https://github.com/dhuzard/diggypaper/pull/12) and [pure scorer in #15](https://github.com/dhuzard/diggypaper/pull/15). It does not select papers, create reviewer judgments, execute models, or report scientific results. The [JSON Schema](../schemas/seip-pilot-manifest-v1.schema.json) defines the wire shape; the [example](../examples/seip-pilot-manifest-draft-v1.json) is deliberately an empty draft with **no papers or results**. Semantic checks are in `app.seip_pilot_manifest`.

Run from `backend`:

```shell
python -m app.seip_pilot_manifest ../docs/examples/seip-pilot-manifest-draft-v1.json
```

The validator reads regular local artifact files relative to the manifest's directory and makes no network calls. Paths cannot escape that directory, including through symlinks; FIFOs/devices are rejected before reading. A manifest is limited to 4 MiB, any individual artifact to 64 MiB, and paper/attempt arrays to 1,000 entries each. Effective input is UTF-8 bytes; hashes use exact bytes without normalization. The implementation computes canonical JSON digests with sorted keys, UTF-8, compact separators, and finite JSON numbers. The optional retained source artifact and required frozen effective-input artifact are checked against their declared SHA-256. When a source artifact cannot be retained locally because of access or licensing, `source.artifact_path` may be `null`; `source.sha256` is then a **claim only**, reported in `source_claim_only`. The exact effective input still must be retained locally for a frozen eligible paper.

Candidate rows use `candidate`, `eligible`, or `excluded`. Frozen manifests require exactly 6 eligible development and 24 eligible held-out papers, no unresolved candidates, and a recorded reason for each exclusion. DOI/PMID/PMCID aliases are canonicalized in the ledger; duplicate eligible aliases or study keys fail. An excluded duplicate can point at its eligible version with `duplicate_of`. All paper rows, including exclusions without `duplicate_of`, form identity chains through shared study keys and DOI/PMID/PMCID aliases; no chain may contain two eligible papers or bridge the development and held-out splits. Study identity without a shared identifier still needs a human duplicate check. The held-out target is eight papers each for JATS, PDF, and abstract-effective-input strata. A deviation is allowed only with a predeclared `stratum_deviation_reason`, and the actual counts remain visible.

The `freeze` contains a SHA-256 of the selected cohort/selection rule/seed and a separate SHA-256 of fixed model, prompt, output schema, software commit, decoding settings, and input policy. The prompt artifact is hash-checked. Declared `prompt_example_paper_ids` may refer only to development papers. The validator cannot inspect an opaque prompt for **undeclared** examples; reviewers must inspect the prompt artifact and its rendering procedure before held-out calls. A model revision may be explicitly unknown (`null`), which limits replay claims.

Each held-out paper must have at least one attempt-ledger row, including a `missing_call` row when no invocation happened. `invalid_json`, `invalid_schema`, `error`, and `declared_valid` are separate recorded states. A `declared_valid` output must be a strict UTF-8 JSON object, but **schema validity is not verified**: this manifest freezes only an output-schema version string, not the schema itself. `invalid_schema` is likewise a producer classification, not independently rechecked. Raw output artifacts are hash-checked where applicable; `missing_call` has no invocation or output claim. Attempts must use the frozen input/configuration hashes and be recorded after the declared freeze time. Retries use contiguous indices and retain every attempt. Only the predeclared `first_attempt` selection rule is accepted; choosing the first "valid" retry would rely on unverified schema classifications. The report states `output_schema_validation: unverified` and includes a digest of all attempt rows. Timestamps and hashes in this **unsigned** file are internally checked but cannot prove that selection really preceded evaluation or that a source license grants redistribution. An independently preserved dated digest or signed archive is needed to establish chronology/authenticity.

`scorer_manifest(manifest, base_dir)` validates the ledger and returns #15's typed `Manifest` with its 30 `PaperAttempt` records, field declarations, seed, and attempt-ledger digest. It requires a nonempty `reference_set_id` but cannot prove the reference set is independently adjudicated or locked. It does **not** manufacture `ReferenceField`, `PaperOutput`, or `EvidenceJudgments`: those must come from the separate frozen reviewer and output artifacts under the protocol. Development papers remain inspectable but outside held-out scoring denominators. This module makes no claim that the pilot has been run or qualified.
