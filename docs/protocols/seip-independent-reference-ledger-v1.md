# SEIP independent-reference ledger v1

This is an offline, unsigned record contract for the [30-paper pilot manifest](seip-pilot-manifest-v1.md) and the [qualification procedure in #12](https://github.com/dhuzard/diggypaper/pull/12). It contains no selected papers, reviewer judgments or scientific results. The [JSON Schema](../schemas/seip-independent-reference-v1.schema.json) describes the wire shape; the [draft example](../examples/seip-independent-reference-draft-v1.json) intentionally contains no references. Semantic checks are in `app.seip_reference_ledger`.

Run from `backend` with the pilot manifest and ledger in that order:

```shell
python -m app.seip_reference_ledger ../docs/examples/seip-pilot-manifest-draft-v1.json ../docs/examples/seip-independent-reference-draft-v1.json
```

A locked ledger must match a fully frozen 6-development/24-held-out pilot manifest by canonical manifest SHA-256 and reference-set ID. It must cover every eligible held-out paper exactly once in each stage; development, excluded and unknown IDs are rejected. Stage A records the frozen source and effective-input hashes, two separate initial judgments for every frozen field, both locked originals, and a third actor's adjudication for every disagreement. Each reported observation requires typed value, scope/unit, section and an exact code-point span in the retained effective input. Other statuses carry a reason and no invented observation. `unclear` remains a valid unresolved outcome. Agreement is derived from the two original field records; an adjudicator cannot silently rewrite either original. A per-paper Stage A lock hashes all its records. No held-out model attempt may precede the latest Stage A lock across all 24 papers, including unselected retries. Stage B records and locks follow that project-wide gate.

A locked ledger also needs an explicit `approved` codebook record naming all three actors, an approval timestamp and the digest of an externally held approval record; pending/draft codebook markers are rejected. The digest is a claim until its external record and signatures are checked. Actor records declare expertise, approval of the exact protocol and codebook versions, and a per-paper pre-review clearance with no conflict or prior model/peer exposure. The validator requires two initial actor IDs and a different adjudicator ID. The provisional real staffing is Damien Huzard and Benoit Petit-Demouliere for initial review and Leonardo Restivo for adjudication; this draft does not assert that their qualifications, approvals or case clearances have been independently obtained. Durable pseudonymous IDs can be used in a private ledger, with identities held separately under the project's access policy.

Stage B starts after Stage A locks and the selected model attempt. It binds each paper to its Stage A lock, effective-input hash and selected output SHA-256, records the proposed answer revision/evidence IDs and quotation, and keeps source occurrence (`exact` with a checked input span, or `unverified` without a verified span) separate from two independent scientific-support judgments. A third actor adjudicates status disagreements, retaining both originals and an explicit reason; unresolved `unclear` survives; `not_assessed` is a pre-review placeholder and blocks a locked link. Zero-link and failed-output cases remain explicit with a reason and a Stage B lock; they are not silently dropped. Exact occurrence never creates a `supports` judgment. The selected output's `declared_valid` state means strict JSON-object syntax only; schema validity is unverified. The current ledger does **not** parse model output to prove that listed answer/evidence links were emitted; the output hash binds the selected output artifact but link inventory still requires independent review. It is not a scorer adapter or a qualified gold record.

The validator rechecks pilot artifact hashes and replays reported observation slices against retained UTF-8 effective input. A source hash without a retained licensed source artifact remains a claim, as in the pilot manifest. Locks and timestamps check internal ordering but are not signatures or trusted timestamps. They cannot prove actual reviewer identity, expertise, independence, absence of conflicts, blinding, source rights, or that reference creation preceded model exposure. Preserve signed qualification/clearance and access evidence separately before calling a set independently qualified; any missing declaration fails locked validation. The draft state reports `pending`, never qualified. No empirical accuracy or support claim follows from a structurally valid ledger.
