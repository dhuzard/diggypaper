# SEIP autonomous implementation plan

Prepared 2026-10-16 for [epic #1](https://github.com/dhuzard/diggypaper/issues/1), using the [scientific evidence audit](../audits/2026-10-scientific-evidence-integrity.md) at baseline `9e5859c1d00921fb19f5c61146deeb39977b2df9`. This assigns bounded engineering work and review; it is not a scientific validation result or an authorization to merge PRs. The audit [PR #8](https://github.com/dhuzard/diggypaper/pull/8) remains documentation only. Independent implementation branches start from the then-current `main` in separate worktrees and identify their base commit. A dependent PR branches from the reviewed prerequisite branch/commit and targets that branch while it remains unmerged; retarget to `main` only after the prerequisite merges. This keeps stacked work reviewable without copying unfinished source changes into parallel branches.

## Outcome and ownership

The minimum useful result is a prediction or human answer whose quoted evidence resolves to a retained article-text version and passage, carries an explicit source-match outcome, can be assessed for scientific support by a human, and survives independent export. A matching substring never becomes a support decision. Historical rows without captured inputs remain explicitly unversioned. The six existing sub-issues remain the workstream; [#9–#11](../audits/2026-10-scientific-evidence-integrity.md#15-adjacent-issues-added-after-the-audit-baseline) are adjacent work, not added SEIP tasks.

| Agent role | Model and effort | Assigned work | Ownership boundary |
|---|---|---|---|
| Integration lead (root) | Current Codex model, high review attention | Freeze interfaces; assign worktrees; review every diff and test result; sequence PRs; maintain epic and decisions | Sole integrator of shared contracts and PR dependency order; does not treat an agent's self-review as approval |
| `seip_provenance` | GPT-6.1 Sol, high | [#2](https://github.com/dhuzard/diggypaper/issues/2): source replacement, additive snapshot/invocation storage, normal/benchmark/scorer capture, review-source binding | Exclusive writer of `db/models.py`, migration(s), `fulltext.py`, `article_text.py` and shared inference/benchmark task files until the base contract merges |
| `seip_evidence` | GPT-6.1 Sol, high | [#3](https://github.com/dhuzard/diggypaper/issues/3) pure matcher and tests; [#4](https://github.com/dhuzard/diggypaper/issues/4) pure evidence/link validator; integrate only after source owner releases shared files | Owns new isolated modules/fixtures first; no concurrent migration or task edits |
| `seip_review_export` | GPT-6.1 Sol, high | [#6](https://github.com/dhuzard/diggypaper/issues/6) immediate human-evidence preservation; then [#5](https://github.com/dhuzard/diggypaper/issues/5) review/gold API and UI; finally #6 portable bundle | Owns crate/export files in its independent early PR; annotation/gold/frontend edits wait for frozen answer-link contract |

Only three subagents may be active alongside root at once. Reuse these roles by wave rather than starting all four together. The named planning agents that reviewed this design did read-only analysis; implementation agents receive fresh, bounded tasks with the model assignments above. The integration lead is responsible for cross-agent context, task boundaries and final PR review. Agent output is draft work until checks and independent review pass.

## Contract to freeze before shared-file edits

The architecture gate is a short reviewed contract with representative JSON fixtures, not a new framework. Decide exact names and storage only after the source owner and assurance reviewer check real call paths. Default: additive source/invocation storage with nullable links on new predictions/reviews, and a versioned evidence/link envelope in existing JSONB; add a dedicated evidence table only if the current query or integrity requirements demonstrate a need. A single owner writes the migration. Required interfaces:

1. **Source snapshot:** stable ID scoped to project/article; retained exact extracted text and SHA-256; identifiers, source type/URL, section map, extraction version and raw-artifact digest/availability. Identical text with different source attribution remains distinguishable. Never infer a historical snapshot from current article text. Capture a coherent source revision in a short transaction, including metadata refresh and import writers. Render and dispatch from its immutable copy; never reread the mutable article when binding the returned prediction, and never hold a database lock across a provider call.
2. **Rendered invocation:** immutable ID, snapshot ID, exact outbound messages/requests and hashes, target-article spans separated from template and few-shot examples, prompt/field/model/software identities, stage, timestamps and explicit unknown provider revisions. Record both prefilter and main calls. SystemOne needs every actual window/detail request; ONNX needs its effective tokenized/truncated input. Backend credentials and headers stay out of captured artifacts.
3. **Review source binding:** GET returns the source token actually displayed; POST carries that token and validates article/project/version. A review submitted after a replacement binds to what the reviewer saw or fails/marks unavailable. A client omitting the token never receives a fabricated assertion that it saw the current text.
4. **Match result:** original quote, verifier version, exact/normalized/not-found/ambiguous/invalid/source-unavailable/not-checked state, source/input ref, bounded candidate spans and truncation flag. Scorers that emit no quotations have producer state `not_produced`; empty quotes do not become verification failures. Legacy quotations without captured input remain `not_checked`. Offsets are zero-based, half-open Unicode code points; JS UTF-16 conversion is explicit. Normalize only under approved NFC/whitespace rules with an original-offset map. No fuzzy matching or semantic claim.
5. **Answer/evidence envelope:** stable server evidence IDs, immutable answer revision plus field key, frozen field-definition identity, many-to-many links, match results and explicit legacy/unlinked state. One canonical representation derives legacy `evidence_quotes`; old clients cannot silently erase structured evidence. Invalid model links are retained as invalid output, not repaired into trustworthy links. Generated prompt/schema instructions must request answer-linked evidence when that contract is active.
6. **Assessment/export:** support outcomes attach to exact answer/evidence revisions and human procedure/actor/time; source authenticity stays separate. An offline bundle reader must resolve references, verify hashes and reproduce quoted slices without database access.

Two current compatibility traps receive explicit fixtures. `create_annotation` rebuilds custom-field payloads and standard Pydantic inputs, so unknown evidence envelopes disappear unless deliberately preserved. `_review_status` compares non-metadata keys, so new envelope metadata must not turn evidence edits into changed-answer status. Inference and benchmark render independently, and the model driver currently returns parsed JSON rather than raw response bytes; capture the real transport/input trace through one adapter without inventing unavailable raw output.

## Review protocol and stop conditions

Every PR includes a concrete before/after example, audited base, affected issue, schema/API compatibility notes, fixture evidence and exact checks run. Root checks the diff and affected tests. `seip_assurance` independently reviews high-risk source/schema, matching, blinded review, export and denominator changes. The author does not provide the sole review. If a review finds a mismatch, the author revises the same PR and reruns affected checks; dependent agents wait for the corrected contract. PRs are not automatically merged, and approval of audit PR #8 is separate from implementation acceptance.

Required engineering checks when relevant: backend Ruff check/format and affected pytest modules followed by full pytest in CI; frontend TypeScript, lint, Jest and build for UI changes; actual PostgreSQL Alembic upgrade/downgrade strategy for storage changes; API isolation/permissions; offline RO-Crate replay. The current audit machine lacked local `asyncpg`, `aiosqlite` and `node_modules`; implementation agents may create isolated virtual environments and run `npm ci` using existing manifests, documenting exact versions and failures. Dependency files change only if justified by a scoped PR. CI currently runs backend and frontend checks but no PostgreSQL migration job, so that migration evidence must be added or supplied separately.

Block any PR that fabricates a historical source version, binds a review to a different displayed text, counts examples as target article evidence, loses a model invocation/window, leaks credentials or blind-review data, silently erases structured records through a legacy client, treats a source match as scientific support, or exports dangling/unreplayable references. These are correctness gates, not optional polish.

Scientific pilot execution has a separate human gate: approve the field definitions and support protocol; freeze 6 development and 24 held-out papers; obtain two independent blinded annotations and a third adjudicator who did not initially label the case; retain original judgments and conflicts. Agents can implement forms, scoring and analysis but cannot create independent gold by pretending to be reviewers. If these reviewers or eligible source rights are unavailable, mark the measured pilot pending while completing software qualification. Do not claim scientific validation from unit tests, exact matching, agreement or gold membership alone.
