# Show only the caller's own review in a blind article list

In a blind search, `GET /projects/{id}/articles` called `latest_reviews()` without restricting
to the caller, so once a member had reviewed an article the item's `review` / `confidence` /
`answers` / `review.by` came from whichever member reviewed it most recently, i.e. another
reviewer's judgment and name.

- `latest_reviews()` takes an optional `reviewer_id`; the list passes `user.id` in blind scope.
- `mine` (articles for which model data may be shown) is derived from that own-only map, which
  drops the separate query that did the same thing.
- Test: A then B review the same article; each list shows only its own review, a third member
  with no review sees none.

Tested: `ruff check`, `ruff format --check`, `pytest tests/test_searches.py tests/test_annotations_api.py tests/test_gold_api.py` (46 passed); the new test fails on `main`.
