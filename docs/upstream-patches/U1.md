# Guard Unix-only `resource` import so the benchmark task loads on Windows

`app/tasks/benchmark.py` imported the Unix-only `resource` module at module level, so on Windows
the Celery worker and every test module that pulls in the benchmark task failed at import.

- Wrap the import in `try/except ImportError` (`resource = None` when unavailable).
- Move the only use into `_peak_ram_mb()`, which returns `None` without the module; Unix
  behaviour (`ru_maxrss / 1024`) is unchanged.
- Test: reloads the module with `resource` blocked in `sys.modules` and checks the RAM figure
  is `None` (platform-independent).

Tested: `ruff check`, `ruff format --check`, `pytest tests/test_benchmark.py tests/test_benchmarks_api.py` (24 passed).
